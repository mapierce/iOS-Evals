# iOS-Evals

A benchmark that measures **API currency**: whether SwiftUI code generated by an
LLM uses APIs that are valid for a pinned SDK and deployment target.

The compiler is the scorer. Code is generated, compiled against a pinned iOS
SDK, and its deprecation and availability diagnostics are counted. Lower is
better.

Two failure modes are measured:

- **Deprecation** — the model emits symbols Apple has deprecated. Compiles with warnings.
- **Availability** — the model emits symbols above the deployment target. Fails to compile.

## Reproducing

```sh
cp .env.example .env      # add an OpenRouter key
python3 run.py
```

One command, from a clean clone, to a dated results file in `results/`.

Requires the exact Xcode and SDK named in `config/pins.toml`; the run refuses
to start on a mismatch rather than producing numbers that cannot be compared.

Ground truth is parsed from the `.swiftinterface` files in the pinned SDK at run
time and is never hand-maintained, so it regenerates as the SDK moves.

## Results

Dated files in [`results/`](results/). Metrics are defined in
[`docs/metrics.md`](docs/metrics.md), frozen before any result was viewed.

A results file carries a warning banner when its corpus is too thin to support
a ranking — between-prompt variance swamps between-model variance until the
churning API families are covered several prompts deep.

## Layout

```
config/       pins.toml — SDK, Xcode, deployment target, model roster
groundtruth/  .swiftinterface parser
prompts/      published corpus
prompts.local/ held-out split (gitignored — publishing it rots the benchmark)
scaffold/     minimal SPM package, baselined at zero warnings
runner/       generation, compilation, diagnostics, AST dump
scoring/      metrics and reporting
results/      dated result tables
```
